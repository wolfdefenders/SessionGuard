FINDINGS - HIGH (5)
----------------------------------------------------------------------------------------------------
[H1] Session cookie missing HttpOnly flag - "sessionid"
     Cookie    : sessionid
     Evidence  : Cookie "sessionid" is set without HttpOnly, so any XSS flaw on this origin can read it via document.cookie and steal the value.
     Fix       : Add the HttpOnly attribute to session cookies so JavaScript cannot read them.
     Reference : OWASP WSTG v4.2 - Session Management Testing
[H2] Session ID not rotated after login
     Cookie    : sessionid
     Evidence  : Pre-login and post-login session identifiers are identical (sessionid=staticsessionid0001). An attacker who learns the pre-login value owns the authenticated session.
     Fix       : Regenerate the session identifier on every privilege change (especially login): invalidate the old ID server-side and issue a fresh one.
     Reference : OWASP Session Management Cheat Sheet
[H3] Session fixation - server accepted the attacker-supplied session ID
     Cookie    : sessionid
     Evidence  : Attacker-supplied value "SGFIX5E78369E" for cookie "sessionid" was still in use after a successful login, so anyone who plants that value in a victim's browser inherits the authenticated session.
     Fix       : Regenerate the session identifier on login (and on any privilege change) and invalidate the attacker-supplied ID server-side.
     Reference : OWASP Session Management Cheat Sheet
[H4] Session ID still accepted after logout
     Cookie    : sessionid
     Evidence  : After logging out, re-using SID "staticsessionid0001" on http://127.0.0.1:5120/profile returned an authenticated response. A stolen or leaked session ID remains usable even after the user logs out.
     Fix       : Delete the server-side session record on logout, invalidate the cookie, and reject unknown/expired IDs on every request.
     Reference : OWASP Session Management Cheat Sheet
[H5] Duplicate session IDs observed (collision)
     Cookie    : sessionid
     Evidence  : Across 8 fresh requests, 1 value(s) repeated, e.g. "staticsessionid0001" issued 8 times. Repeated IDs point to a broken or static generator.
     Fix       : Generate every session ID from a CSPRNG; never reuse values across sessions.
     Reference : OWASP Session Management Cheat Sheet

FINDINGS - MEDIUM (7)
----------------------------------------------------------------------------------------------------
[M6] Session cookie missing Secure flag - "sessionid"
     Cookie    : sessionid
     Evidence  : Cookie "sessionid" is set without the Secure flag, so it can also travel over plain HTTP. The target itself is served over http:// (private/lab host)
     Fix       : Add the Secure attribute so the cookie is only sent over HTTPS.
     Reference : OWASP WSTG v4.2 - Session Management Testing
[M7] Session cookie has no SameSite attribute - "sessionid"
     Cookie    : sessionid
     Evidence  : Cookie "sessionid" declares no SameSite attribute. Modern browsers default to Lax, but older or embedded browsers may not, leaving the cookie exposed to cross-site requests (CSRF).
     Fix       : Set SameSite=Lax or SameSite=Strict explicitly.
     Reference : OWASP WSTG v4.2 - Session Management Testing
[M8] SameSite=None without Secure on cookie "analytics"
     Cookie    : analytics
     Evidence  : Cookie "analytics" declares SameSite=None but not Secure. This combination is invalid per RFC6265bis: modern browsers reject the cookie, and if it were accepted it would be sent on every cross-site request.
     Fix       : Use SameSite=Lax (or Strict), or add the Secure flag when SameSite=None is really required.
     Reference : OWASP WSTG v4.2 - Session Management Testing
[M9] Weak session ID entropy - "sessionid"
     Cookie    : sessionid
     Evidence  : Value "staticsessionid0001" (length 19, alphabet base36): Shannon entropy 3.22 bits/char, ~61 bits total. estimated entropy is ~61 bits - below the 64-bit recommendation.
     Fix       : Generate session IDs from a CSPRNG with at least 128 bits of entropy (e.g. secrets.token_bytes(16)).
     Reference : OWASP Session Management Cheat Sheet (>= 64 bits of entropy)
[M10] Cookie prefix rule violation - "__Host-cfg"
     Cookie    : __Host-cfg

METHODOLOGY & SEVERITY MODEL
----------------------------------------------------------------------------------------------------
- Entropy is measured as Shannon entropy of the character distribution (bits/char)
  multiplied by length for estimated total bits; OWASP recommends >= 64 bits.
- HIGH: accepted fixation, no rotation, session still valid after logout, missing HttpOnly on a
  session cookie, SameSite=None without Secure, duplicate / sequential session IDs, predictable
  values, plaintext HTTP on a public host.
- MEDIUM: missing Secure on a session cookie, missing SameSite, short or low-entropy IDs, prefix
  rule violations, shared ID prefixes.
- LOW / INFO: advisory scope findings, non-session cookie flag gaps, inconclusive tests.
- Rotation / fixation / logout tests need lab credentials in Settings; without them they are
  reported as INFO (not tested).
- LAB-ONLY: test only systems you own or have written permission to test. Unauthorized access
  is a criminal offence under the Prevention of Electronic Crimes Act, 2016 (Pakistan).
